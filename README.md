更新日期：2026-10-18。

## 二、游戏有哪些功能，怎么玩

### 1. 默认奖励与界面

- 保留原来的 48 种真实奖励，新增 12 种盲盒，共 60 种奖励，另有 1 个“谢谢惠顾”结果。
- 默认实际概率：原有奖励合计 60%，新增盲盒合计 10%，“谢谢惠顾”30%。后续修改权重或停用奖品后，以编辑器计算的结果为准。
- 玩家界面不显示每件奖品的概率，也不显示预算字段；编辑器会显示，便于你安排。
- 盲盒在奖品清单里只显示封面名称和提示，刮开后才揭晓真实奖品名称、兑现内容和留言。
- 抽奖次数不限，没有“本轮还剩几次机会”的限制。先揭晓当前结果，再继续下一次。
- 刮卡进度用文字提示，玩家页面不显示刮开百分比。

### 2. 一次抽奖的流程

1. 打开正式游戏网址，点击抽奖。
2. 转盘开始转动；本次结果在抽奖开始时就已确定并保存。
3. 转盘停下后刮开卡片，查看奖励；不方便手指刮卡时，也可以使用页面提供的直接揭晓功能。
4. 抽到奖励后，在奖券列表中查看，按需要保存奖券图片，与另一方商量兑现。
5. 兑现后可在页面中标记状态；先完成当前揭晓，再继续抽奖。

“谢谢惠顾”是未中奖结果，不能作为奖励兑换。盲盒是一次抽奖中的一种奖品，刮开只负责揭晓，不会再随机抽第二次，也不是额外赠送一次机会。

关闭、刷新或重新打开同一页面，可以继续之前未刮开的结果，不会因此重新换奖品。记录保留的条件见第十二节。

解压 `love-wheel-mystery-complete.zip`，打开最外层的 `love-wheel-mystery` 文件夹。

本次扩写 README 不会自动改变你此前下载的 ZIP，也不会自动改写 GitHub 文件。可以把本 README 放到解压目录中一并保存。

| 仓库中的路径 | 作用 |
|---|---|
| `README.md` | 仓库首页的说明文档 |
| `dist/index.html` | 游戏入口；采用本手册日常流程后是完整单文件游戏 |

## 四、第一次上传，或从当前拆分版切换到单文件版

### 1. 准备好要发布的内容

想使用默认配置，可以取完整包最外层的 `index.html`。如果已经改过奖品，先在编辑器导入最新的配置 JSON，检查内容，再导出完整首页；不要用初始配置覆盖自己的修改。

编辑器不会自动读取当前线上游戏的配置。没有 JSON 时，先确认编辑器中的内容就是你想发布的版本；仍有旧浏览器草稿时，可在那里打开工具并导出备份。

### 2. 上传游戏和编辑器

1. 登录 GitHub，打开[仓库已有的 dist 文件夹](https://github.com/bbtnoctrl/love-wheel/tree/main/dist)。
2. 确认分支为 `main`，目录是 `love-wheel / dist`。
3. 点击 **Add file → Upload files**。
4. 上传准备好的完整 `index.html`，覆盖该目录的同名文件。
5. 要在线使用编辑器时，上传完整的 `love-wheel-editor.html`，保留原文件名。当前已上传且工具版本相同时无需重复替换。
6. 点击 **Commit changes**，提交到 `main`。若使用新分支或 Pull Request，则需合并到发布分支后才会发布。
7. 等待 Pages 完成发布，在 **Actions** 中检查结果，然后从正式游戏网址打开。

上传方式参考 [GitHub 官方文件上传说明](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)。不要直接上传 ZIP 等待 GitHub 自动解压，也不要把目录放成 `dist/dist/`。

### 3. 上传 README

回到[仓库根目录](https://github.com/bbtnoctrl/love-wheel)，上传本文件，与 `dist` 文件夹同级。

文件名使用 `README.md`。如果下载时自动变成 `README(1).md`、`README(2).md` 或其他带编号的名称，上传前改回 `README.md`。Markdown 说明不会替代 `/dist/` 中的游戏。

### 4. GitHub Pages 设置

进入 **Settings → Pages**，按当前仓库结构使用：

| 设置 | 选择 |
|---|---|
| Source | `Deploy from a branch` |
| Branch | `main` |
| Folder | `/(root)` |

发布源选择仓库根目录；游戏作为其中的 `dist` 子目录，通过 `/love-wheel/dist/` 访问。无需为这次更新重建仓库或更改正式网址。

提交后的发布可能需要约 10 分钟，具体以 **Actions** 的发布结果为准。参见 [Pages 发布源说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) 与 [Pages 发布和访问说明](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)。

完成单文件切换后，旧 `app.js`、`core.js`、`config.js`、`styles.css` 等可以继续保留，完整首页不会读取它们。当前尚未切换时，拆分版所需文件仍要保留。

## 五、打开编辑器，确认正在修改哪份配置

### 1. 在线打开

访问[在线参数编辑器](https://bbtnoctrl.github.io/love-wheel/dist/love-wheel-editor.html)。打开编辑器本身不用登录 GitHub；上传修改后的文件时才需要你的仓库操作权限。

### 2. 本地打开

把完整 `love-wheel-editor.html` 保存到电脑，用浏览器直接打开。普通使用不需要安装 Node、Python 或其他开发软件，也不需要启动服务器。

### 3. 编辑器的配置从哪里来

编辑器首先使用文件内置的配置，再尝试读取当前浏览器在同一站点下保存的有效草稿；你也可以主动导入配置 JSON。

**它不会自动读取线上 `index.html`、`config.js`，也不会自动把编辑结果写回 GitHub。** 已经发布新的游戏首页，不会同步改写编辑器内置的初始配置。

因此，下一次修改前先确认页面文案、奖品和概率是不是上次保存的版本。换电脑、换浏览器，或从本地工具换到在线工具时，优先导入最近的 JSON 备份。

本地草稿和玩家奖券是不同数据。修改编辑器参数不会直接清空她的奖券，但发布时仍应保留已有奖品 ID，详见第十二节。

在编辑器左侧“专属设置”中填写，右侧会显示当前配置概览。

| 编辑器中的参数 | 配置字段 | 默认值 | 允许范围与说明 |
|---|---|---|---|
| 小站名字 | `siteTitle` | 偏爱福利社 | 1–24 个字符 |
| 给她的称呼 | `recipientName` | 宝宝 | 最多 20 个字符，可留空 |
| 主标题前半句 | `heroPrefix` | 今天也 | 最多 16 个字符，可留空 |
| 主标题强调词 | `heroHighlight` | 偏爱你 | 1–16 个字符 |
| 一句悄悄话／首页副标题 | `subtitle` | 好运归你，兑现归我。 | 1–120 个字符 |

## 七、修改、增加或停用奖励

### 1. 找到想修改的奖品

在“奖品编辑”区域按名称、内容或谜面搜索，也可按分类、参与状态和盲盒状态筛选。点击奖品卡片展开。

| 字段 | 作用 | 允许范围或注意事项 |
|---|---|---|
| 真实奖品名称 | 揭晓后的奖品标题 | 1–80 个字符 |
| 具体承诺／奖品内容 | 写清物品、次数、时长、金额或兑现安排 | 1–500 个字符 |
| 一句小备注 | 揭晓时的留言 | 1–240 个字符 |
| 相对权重 | 决定它在真实奖励中所占的相对机会 | 1–100000 的正整数，权重不等于百分比 |
| 预计预算 | 方便你安排支出 | 0–1000000 元，不控制概率，不会自动付款 |
| 参与抽奖 | 决定此奖品是否继续参与 | 取消勾选后不再抽到，也不出现在玩家奖品清单中 |
| 设为盲盒 | 在刮开前使用封面信息 | 开启后必须填写谜面和提示 |
| 盲盒谜面／封面名称 | 玩家刮开前看到的标题 | 1–40 个字符 |
| 盲盒提示 | 提供悬念和线索 | 1–240 个字符，尽量不要把答案直接写出来 |

预算只是你自己安排支出的字段。比如将预算从 50 改为 80，不会自动把“具体承诺”中的“50 元礼物”改成“80 元礼物”；兑现约定需要同时修改正文。

### 2. 添加一件普通奖励

1. 点击 **“添加奖品”**。
2. 选择一个已有分类。
3. 填写真实名称、具体承诺、小备注、相对权重和预算。
4. 保持盲盒选项关闭，点击添加。
5. 检查新增卡片和自动重算的概率。

编辑器自动生成唯一 ID，并把新奖品追加到所选分类末尾。当前表单可以向现有分类添加奖品；新增分类或修改分类名称、颜色、图标，需要进一步修改配置源码。

### 3. 添加盲盒，或将普通奖品改成盲盒

添加或编辑奖品时，勾选 **“设为盲盒”**，填写真实内容，再填写“盲盒谜面”和“盲盒提示”。

例如，真实奖励可以写“周末早餐我来准备”，封面写“清晨的一份偏爱”，提示写“不用早起，也能接住热乎乎的心意”。玩家先看到封面和提示，刮开后再看到真实承诺。

### 4. 不想继续发某个奖品

取消勾选该奖品的 **“参与抽奖”** 即可停用。停用条目仍保留原来的正权重和 ID，但实际抽奖权重按零处理。

保留已有奖品 ID，不要删除、改名或挪动标识。旧券保存的是中奖时的快照，改文案或停用不会把原承诺替换掉。导入配置时也会检查已有分类和奖品的 ID、顺序，避免旧记录失去对应关系。

### 5. 其他限制

- 总条目上限为 300，包含已停用奖品和“谢谢惠顾”。
- 至少保留一件真实奖励参与抽奖。
- “谢谢惠顾”不能停用或设为盲盒，其概率通过专属设置中的独立参数修改。
- 页面出现校验错误时，先按提示修正，再保存、预览或导出。

## 八、概率和权重怎么理解

### 1. 默认分配

| 结果类别 | 默认合计概率 |
|---|---:|
| 原来的 48 种奖励 | 60% |
| 新增的 12 种盲盒 | 10% |
| 谢谢惠顾 | 30% |
| 总计 | 100% |

这是初始配置的分配。修改奖品权重、添加奖品或停用奖品后，普通奖励与盲盒会重新分配“谢谢惠顾”之外的份额。

### 2. 相对权重不是直接填写百分比

权重 100 不表示 100%。在同一次配置中，权重为 200 的真实奖励，抽到的概率是权重为 100 的真实奖励的两倍。

计算规则为：

> 某件真实奖励的实际概率 =（100% − 谢谢惠顾比例）× 该奖励权重 ÷ 所有参与抽奖的真实奖励权重之和。

普通奖励和盲盒都计入“真实奖励”；停用的条目不参与权重总和。

例如，仅为说明算法，假设只启用 A、B 两件真实奖励，“谢谢惠顾”保持 30%。A 权重为 100、B 为 300，则 A 是 17.5%、B 是 52.5%，谢谢惠顾仍为 30%。将 A 的权重也改成 300 后，A、B 各为 35%，谢谢惠顾仍为 30%。

因此，调高某一件奖品的权重时，其他真实奖励的份额会相应下降；编辑器会自动重算，无需手动把每件奖品凑成 100%。

### 3. 谢谢惠顾怎么修改

在“专属设置”中修改 **“谢谢惠顾概率”**。想继续保持原方案就填 30。

不要通过“谢谢惠顾”条目的原始权重来调整它的概率；这个条目的实际抽奖权重由独立比例参数重新计算。

30% 表示每次抽取的概率，不代表每 10 次一定出现 3 次。连续抽到同一结果或短时间没有出现某种奖励，都可能发生。

## 九、保存草稿、备份配置和发布的区别

| 操作 | 保存到哪里或产生什么 | 会更新女朋友看到的游戏吗 |
|---|---|---|
| 修改编辑器中的字段 | 当前打开的页面 | 不会 |
| 点击“保存本地草稿” | 当前浏览器的本地存储 | 不会 |
| 点击“导出配置 JSON” | 下载可再次导入的参数备份 | 不会 |
| 点击“导出网页 index.html” | 下载包含当前参数的完整游戏文件 | 不会 |
| 上传新版 index.html，并提交到发布分支 | 更新仓库文件，随后由 Pages 发布 | 发布成功后会 |

### 1. 本地草稿要手动保存

点击 **“保存本地草稿”** 后，检查工具显示的保存状态。编辑器没有持续自动保存功能；导出网页也不会自动替你保存草稿。

同一站点、同一浏览器中的同款编辑器可以读取本地草稿。换浏览器、换设备、清理数据，或从本地文件切换到网站时，不能依赖原来的草稿一定可读。

如果浏览器不允许保存，工具会提示失败；仍然可以继续编辑和导出，请及时保存 JSON。离开未保存页面时，工具会尝试给出提示，但不能把提示当作备份。

### 2. JSON 才是方便继续修改的参数备份

点击 **“导出配置 JSON”**，保存当前配置。可以在电脑上用日期或版本区分备份，例如 `love-wheel-config-2026-10-18.json`；导入时选择你最近一次确认过的版本。

**配置备份只包含奖品和参数，不包含她的中奖记录。** 它也不是能直接运行的游戏，上传 JSON 不会让完整单文件首页自动读取新内容。

### 3. 下次如何继续修改

1. 打开在线或本地编辑器。
2. 检查是否已恢复正确的本地草稿。
3. 如不一致或换了设备，点击 **“导入配置 JSON”**，选择最近备份。
4. 确认称呼、奖品、盲盒和概率设置后，再开始修改。
5. 完成后重新保存草稿，并导出一份最新 JSON。

JSON 导入上限为 2 MB。导入会检查配置格式、参数范围、现有分类和奖品的 ID 与顺序；缺少已经追加过的奖品、删除或移动已有条目时会被阻止。旧备份可能因此无法直接覆盖当前配置，此时应使用完整的新备份，或保留已有条目并停用不想继续使用的奖品。

## 十、以后修改完，怎样更新给女朋友

**每次更新都按这个顺序：确认最新配置 → 修改 → 导出 JSON → 预览 → 导出 index.html → 上传覆盖 → 等待发布 → 原链接检查。**

1. 在编辑器中导入或确认最新配置，完成修改。
2. 修正所有校验提示；保存本地草稿，并点击 **“导出配置 JSON”** 留备份。
3. 点击 **“玩家清单预览”**，检查卡片文案和盲盒谜面。预览只展示奖品卡片，不是完整转盘或刮卡实测。
4. 点击主按钮 **“导出网页 index.html”**，下载新的完整游戏首页。
5. 若文件被命名为 `index (1).html` 或其他编号，先把这次新导出的文件改回 `index.html`。
6. 打开[仓库已有的 dist 文件夹](https://github.com/bbtnoctrl/love-wheel/tree/main/dist)，选择 **Add file → Upload files**。
7. 上传并覆盖 `index.html`，确认选中的是新文件，提交到 `main`。
8. 等待 **Actions** 中 Pages 发布成功，再访问[原游戏网址](https://bbtnoctrl.github.io/love-wheel/dist/)，检查文案、奖品清单及抽奖揭晓。

本地编辑、保存草稿、导出 HTML 或 JSON，都不会自动修改 GitHub；完成上传与发布后，其他设备才会看到变化。

### 日常要重新上传编辑器吗

只改参数或奖品时，通常只需上传新的游戏 `index.html`。编辑器文件可以继续使用，但下次打开仍应依靠最新草稿或 JSON 恢复参数，因为发布游戏不会更新编辑器的内置默认配置。

如果以后修改了游戏功能代码或编辑器本身，则要使用重新构建的新版编辑器。它内部保存着生成游戏所需的代码，旧工具可能重新导出旧功能版本。源码更新方法见第十四节。

### 网址和二维码要换吗

只要仓库、文件目录和正式地址保持不变，就继续使用第一节的游戏网址，原二维码也继续有效。更新内容无需修改游戏页面地址，不要为了刷新而在网址后增加查询参数。

## 十二、旧奖券、兑现记录、网址和二维码

### 1. 更新参数后，原来的奖券怎样处理

原有奖品 ID 和默认顺序已保留。奖券保存中奖当时的名称、兑现内容、留言等快照，更新文案不会把旧承诺变成另一份奖励。

停用奖品只影响之后的抽取；已经抽到的券仍然可以按原承诺兑现。未刮开的结果也会继续保留，刷新或更新后不会重新抽一次。

奖券不设过期时间，兑现时间由你们一起商量；网页负责记录，不会自动付款或购买。

为了维持兼容，请通过“参与抽奖”开关停用奖品，保留原 ID。导入工具会检查既有条目，帮助避免误删。

### 2. 记录保存在哪里

奖券保存在玩家当前浏览器的网站数据中。保持同一浏览器、同一正式网址、保留网站数据，并保留已有奖品 ID，才能继续沿用旧记录。

换手机、换浏览器，或者在聊天软件内置浏览器与系统浏览器之间切换，可能看到另一份记录。建议她固定使用同一个浏览器打开正式游戏地址。

“标记已兑现”只改变当前浏览器里的记录；你在另一台设备上不会自动收到同步。奖励由两人沟通兑现，页面不会自动付款或代为购买。

### 3. 为什么不要随便改页面地址

本游戏在浏览器按站点隔离存储的基础上，还使用页面的路径和查询参数区分奖券记录。

| 打开的地址形式 | 对本项目记录的影响 |
|---|---|
| `/love-wheel/dist/` | 正式推荐地址，保持使用这一份记录 |
| `/love-wheel/dist/index.html` | 可能显示同一游戏，但使用不同的奖券存储键 |
| `/love-wheel/dist/?v=2` | 查询参数不同，会使用另一份奖券记录 |
| `/love-wheel/dist/#tickets` | 页内定位不改变奖券存储键 |

静态资源的版本参数由导出工具处理，不需要你给游戏页面网址手动加参数。看到旧页面时先确认发布完成，再刷新或强制刷新；不要通过清除网站数据来更新页面。

### 4. 奖券图片、备份和云同步

游戏可以保存奖券图片，便于展示中奖内容和沟通兑现。图片不能重新导入来恢复整个奖券列表，参数 JSON 也不能用来恢复中奖记录。

当前没有账号、云端奖券同步、远程后台核销或可恢复的整份奖券备份功能。重要的已中奖内容可以另外保留图片并与对方确认。

### 5. 给她分享网址或二维码

优先发送第一节的正式游戏链接。若使用游戏里的分享功能，请先在正式网址打开游戏；分享二维码在浏览器中生成，指向当前页面的实际网址。

在电脑上用 `file://` 打开本地游戏文件，只能本地运行，那个地址不能直接给另一部手机访问。先发布到 GitHub Pages，再分享线上链接或对应二维码。

原来指向 `https://bbtnoctrl.github.io/love-wheel/dist/` 的二维码可以继续使用。公开链接是否能在她的网络中打开，仍以她实际访问为准；页面响应检查不等于已测试她的手机网络。

## 十三、各个源码文件分别做什么

下面的路径都相对于完整压缩包最外层的 `love-wheel-mystery/`。`source/` 中共包含 25 个源码、构建、说明和检查文件；日常用编辑器改奖品时不需要逐个处理它们。

### 1. source/dist 中的 10 个拆分版运行文件

| 文件路径 | 作用 | 什么情况下会用到 |
|---|---|---|
| `source/dist/index.html` | 拆分版页面结构，引用外部 JS、CSS | 维护拆分版时作为入口，不能单独使用 |
| `source/dist/app.js` | 转盘绘制与动画、刮卡、奖品清单、盲盒展示、奖券列表、兑现、图片和分享交互 | 修改游戏界面或交互功能 |
| `source/dist/styles.css` | 颜色、布局、手机适配、组件与动画样式 | 修改游戏外观 |
| `source/dist/core.js` | 按权重选奖、保存中奖快照、读取旧券、揭晓和兑现状态、转盘扇区数据 | 修改抽奖和奖券处理逻辑 |
| `source/dist/config.js` | 保存页面设置和所有奖品：名称、正文、留言、权重、预算、启用状态、盲盒封面与提示 | 修改配置源码或核对奖品数据 |
| `source/dist/config-schema.js` | 参数校验、实际权重与概率计算、固定谢谢惠顾比例、安全输出配置 | 修改校验或计算规则，日常一般保持原样 |
| `source/dist/share.js` | 生成游戏分享链接和二维码 | 修改分享逻辑 |
| `source/dist/assets/icon.svg` | 网页小图标 | 修改网站图标 |
| `source/dist/vendor/qrcodegen.js` | 内置二维码生成库 | 由分享功能调用，无需第三方二维码生成服务 |
| `source/dist/vendor/LICENSE-qrcodegen.txt` | 二维码库的许可证 | 分发源码时保留 |

**config 两个文件的区别：**`config.js` 存“设置与奖品内容”；`config-schema.js` 存“怎样检查设置、怎样计算抽奖权重”。修改奖励通常属于前者；参数编辑器已经帮你操作并检查这些数据。

另一个 `love-wheel-config.json` 是可导入编辑器的配置备份。它与 `config.js` 的内容用途相关，但文件格式和使用位置不同：JSON 是备份输入，JS 是拆分版程序模块。

使用完整单文件 HTML 时，上述运行代码已合并到首页。源码保留为可继续开发的版本，不会被完整首页自动读取。

### 2. source/editor 中的 4 个编辑器源码文件

| 文件路径 | 作用 |
|---|---|
| `source/editor/editor-template.html` | 编辑器页面模板，构建时注入脚本、样式、默认配置和运行文件 |
| `source/editor/editor.css` | 编辑器外观、表单和响应式布局 |
| `source/editor/editor.js` | 表单输入、搜索筛选、添加奖品、校验提示、草稿、JSON 导入导出、预览和导出按钮 |
| `source/editor/export-utils.js` | 生成配置模块、合并完整游戏 HTML、生成多文件 ZIP、更新拆分文件的资源版本引用 |

这四个是制作编辑器的源码。给自己直接打开的成品是最外层的 `love-wheel-editor.html`，它已包含所需代码。

### 3. source 中的构建和项目说明

| 文件路径 | 作用 |

| `source/build-singlefile.py` | 把 `dist/` 合成为完整游戏 `love-lucky-wheel-single.html` |

| `source/checks/README.md` | 介绍检查命令和覆盖范围；不是仓库根目录的本 README |
| `source/checks/run-tests.mjs` | 运行全部自动检查的入口 |
| `source/checks/test-helpers.mjs` | 检查共用的存储模拟、配置变体、抽奖和旧券辅助函数 |

### 5. 构建后才生成的文件

| 生成文件，位于 source 目录中 | 如何使用 |
|---|---|
| `love-lucky-wheel-single.html` | 复制一份并改名为 `index.html`，再上传到仓库已有 `dist/` |

构建生成文件、下载目录里的同名文件与原始源码不是自动同步的。修改源码后需要重新构建；修改编辑器参数后需要重新导出。

## 十四、需要修改源码时，怎样构建和发布

普通奖品、称呼、权重和盲盒修改优先使用参数编辑器。要改页面布局、增加游戏功能或改变程序规则时，再处理源码。

### 1. 修改配置源码的注意事项

`source/dist/config.js` 中保存 `GAME_CONFIG`。保留既有分类和奖品的唯一 ID；不想继续抽到的奖品设置为停用。

构建编辑器时，脚本会按 JSON 解析配置主体。手动修改配置时保持生成文件的写法：键和文字使用双引号，主体不加入 JavaScript 表达式、注释或尾随逗号。其余参数范围与编辑器校验一致。

改“谢谢惠顾”比例使用 `settings.noPrizePercent`，不要只改该条目的原始 `weight`。工具对分类新增没有表单支持；高级修改仍需满足唯一 ID、保留旧条目等兼容要求。

### 2. 生成完整游戏和编辑器

准备 Python 3，进入解压包里的 `source` 目录执行：

```bash
python3 build-singlefile.py
python3 build-editor.py
```

Windows 已安装 Python 3 时，可以执行：

```powershell
py -3 build-singlefile.py
py -3 build-editor.py
```

第一条命令生成 `love-lucky-wheel-single.html`，复制并命名为 `index.html` 后上传。第二条命令生成包含当前游戏源码的 `love-wheel-editor.html`。

构建脚本使用 Python 3 标准库。普通打开游戏和编辑器不需要 Python，也不用安装 npm 或 pip 包。

### 3. 功能代码更新时同时更新编辑器

游戏功能源码更新后，先构建新版编辑器，在其中导入自己最新的配置 JSON，确认奖品和参数后导出完整 `index.html`，再把这个首页和新版 `love-wheel-editor.html` 上传到仓库原来的 `dist` 目录。

如果源码里的配置本身就是你确认的最新版，也可以直接使用构建出的完整游戏。已经定制过参数时，先恢复并确认配置，再发布，避免把初始配置上传覆盖。

**旧编辑器内嵌的是旧运行代码。只更新游戏、继续使用旧编辑器导出，可能又把游戏变回旧功能版本。** 参数备份用于保留你的奖品设置，重新生成编辑器用于带入新的功能代码，这两件事都需要处理。

### 4. 运行源码检查

准备 Node.js 和 Python 3，在 `source` 目录执行：

```bash
node checks/run-tests.mjs
```

这些检查使用项目代码和标准库。交付版本的检查覆盖默认奖品、权重和旧券等行为；如果你有意修改默认奖品总数或权重，针对默认值的断言也可能需要同步调整，不能据此直接认定新参数无效。

## 十五、如果仍然想整套上传拆分版

整套拆分版也可以使用，但要维护完整的一套文件。

### 1. 使用完整包中的初始拆分源码

进入解压包的 `source/dist/`，把**里面的全部文件和子文件夹**上传到仓库已有的 `dist/`，覆盖同名文件。最终入口仍然是仓库的 `dist/index.html`，不是 `dist/dist/index.html`。

这会使用包内配置。如果已经修改过奖品，不要反复拿初始包覆盖自己的最新参数。

### 2. 使用编辑器导出的多文件 ZIP

1. 在编辑器中导入或确认最新配置。
2. 点击 **“导出多文件源码 ZIP”**。
3. 解压下载的 ZIP。
4. 将解压后里面的全部运行文件和子目录上传到仓库已有 `dist/`，覆盖并提交。
5. 等待发布完成，用原网址检查。

工具导出的 ZIP 已包含运行文件，并处理资源引用版本。切换到拆分方式时必须上传整套文件，不能只上传其中的 `index.html`。

### 3. 两种维护方式对照

| 维护方式 | 游戏读取什么 | 日常修改后上传什么 |
|---|---|---|
| 完整单文件版 | `index.html` 内置的全部代码和参数 | 编辑器导出的完整 `index.html` |
| 拆分版 | `index.html` 加载同目录的 JS、CSS 和资源 | 最新的整套运行文件 |

完整编辑器自身始终可以独立运行，不需要旁边的 config 文件。游戏是否需要外部文件，则取决于实际采用的入口版本。后续以单文件方式维护更省操作。

## 十六、常见问题和排查顺序

### 1. 现在到底能不能只留两个 HTML

可以采用两个完整 HTML 的方式，但**本次核对时线上游戏仍是拆分版**。先通过编辑器导出完整 `index.html` 并上传覆盖，再采用单文件维护。切换前保留现有配套 JS、CSS、config 和资源。

完整单文件切换后，旧文件可以继续放着，不影响运行，不必为了使用新版本专门清理它们。

### 2. 为什么改了 config.js，游戏没有变化

若游戏已经换成完整单文件首页，它不会读取外部 `config.js`。请通过编辑器修改并重新导出首页，或者修改源码后重新构建完整首页。

若游戏仍为拆分版，则需要确认上传到了正确目录、发布已完成，并且浏览器正在读取更新后的资源。日常使用编辑器导出的最新完整包可以减少遗漏。

### 3. 上传后还是旧奖品、旧文案或旧概率显示

按顺序核对：

1. 文件是否在仓库 `dist/index.html`，而非根目录、`dist/dist/` 或 `index (1).html`。
2. 是否只保存了草稿、只导出了文件，或只上传了 JSON，还没上传游戏首页。
3. 上传的是不是本次新导出的文件。
4. **Actions** 中发布是否成功；若未完成，先等待。
5. 从正式网址重新打开，必要时使用浏览器强制刷新，保留网站数据。

玩家游戏界面应隐藏概率；编辑器显示概率属于正常配置功能。请先确认打开的是游戏网址还是编辑器网址。

### 4. 为什么编辑器显示初始奖品，而游戏已经改过

编辑器不自动读取线上配置。导入最近一次保存的 JSON，或者在保存过草稿的原浏览器中打开工具。发布新版游戏不会同步改写编辑器内置配置。

### 5. 导入 JSON 被拒绝怎么办

先确认选的是工具导出的配置 JSON，文件不超过 2 MB。按校验提示修正范围、缺失字段或 ID 问题。

如果备份比当前配置更旧，可能缺少后来新增的奖品，兼容检查会阻止覆盖。保留最新备份，使用停用处理不再想抽到的条目。

### 6. 编辑器打不开、按钮没有作用

确认使用的是完整 `love-wheel-editor.html`，而不是源码目录中的 `editor-template.html`，也不是未下载完整的文件。用支持 JavaScript 的浏览器打开，并查看页面是否显示校验或初始化错误。

有未填写或不合法的参数时，导出按钮会停用；先修正校验提示。草稿保存失败不妨碍导出有效配置。

### 7. 女朋友打开不了，或点进去是仓库文件列表

确认发给她的是 `https://bbtnoctrl.github.io/love-wheel/dist/`，而不是 `github.com` 仓库地址、本地文件路径、编辑器或代码预览页。

出现 404 时，检查发布分支、文件名、目录层级和 Pages 状态。如果发布已成功，可用手机系统浏览器打开正式网址确认；不同网络的访问情况仍需实际核对。

### 8. 换设备后奖券不见了，如何找

先回到原来使用的手机、浏览器和完全相同的正式网址。聊天软件内置浏览器、另一浏览器或带不同查询参数的网址，可能显示另一份记录。

本项目没有云端奖券同步；参数 JSON 和奖券图片不能恢复完整奖券列表。不要为了解决缓存而清除原浏览器的网站数据。

### 9. 公开编辑器后，别人能改我的网站吗

别人可以在自己的浏览器里查看和编辑配置，也能导出自己生成的文件，但这些操作不会自动写入你的 GitHub 仓库。真正更新网站仍需要仓库写入权限并完成发布。

编辑器没有登录保护，公开后能访问链接的人可以查看真实奖品和概率。盲盒只在正常游戏界面中隐藏内容，源码与本完整手册中的配置并未加密。

### 10. 普通使用需要安装软件或付费服务器吗

给她打开游戏、你在浏览器里编辑参数，都不需要安装开发环境。当前方案继续使用已有 GitHub Pages；GitHub 官方说明公共仓库可在 GitHub Free 下使用 Pages，见下方官方参考。

进一步修改源码并执行构建时才需要 Python 3，运行检查时还需要 Node.js。维护本项目不要求购买独立服务器。
