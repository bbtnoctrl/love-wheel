## 一、这次增加了什么

- 保留原来的 48 种真实奖励，新增 12 种盲盒，共 60 种奖励，另有“谢谢惠顾”。
- 默认实际分配：原有奖励合计 60%，新增盲盒合计 10%，“谢谢惠顾”30%。这些数字供你配置时查看，玩家界面不显示概率。
- 盲盒在奖品清单里只显示封面名称和提示；抽中后仍需刮开，才出现真实奖品名称、兑现内容和留言。
- 抽奖时一次性确定结果并保存。刮开盲盒只是揭晓，不会再次随机抽取，也不会关闭重开就换奖品。
- 抽奖次数不限。先刮开当前结果，再继续下一次。
- 新增可离线打开的参数编辑工具，可修改称呼、标题、奖品内容、权重、预算、盲盒提示和部分动画参数。
- 刮卡进度改用文字提示，玩家页面不显示刮开百分比。

**本次提供的是已制作好的文件。需要你上传首页到 GitHub 后，线上网站才会变成盲盒版。**

|---|---|

## 三、第一次更新你现在的网站

游戏继续使用原来的地址：

[https://bbtnoctrl.github.io/love-wheel/dist/](https://bbtnoctrl.github.io/love-wheel/dist/)

1. 下载并解压完整压缩包，找到最外层的 **`index.html`**。
2. 登录 GitHub，打开[仓库已有的 dist 文件夹](https://github.com/bbtnoctrl/love-wheel/tree/main/dist)。确认分支为 `main`，路径显示 `love-wheel / dist`。
3. 点击 **Add file → Upload files**。
4. **只上传这次最外层的完整 `index.html`**，替换该目录原来的 `index.html`。
5. 点击 **Commit changes**，直接提交到 `main`。
6. 等待 Pages 自动发布，再从原游戏网址打开检查。

Pages 继续保持 `main` + `/(root)`，不需要重建仓库或改网站地址。提交后可在仓库 **Actions** 查看发布状态。GitHub 官方说明更新可能需要约 10 分钟。

**这次开始推荐用单文件首页维护。** 完整 `index.html` 已包含所有运行代码，不需要再分别上传 `app.js`、`core.js`、`config.js` 或样式文件。仓库中以前的拆分文件可继续保留，但这个完整首页不会读取它们。

不要把 `source/dist/index.html` 当成完整首页上传：它是拆分源码的入口，需要其他文件配合。不要直接上传整个 ZIP 等待 GitHub 自动解压，也不要把首页放到 `dist/dist/`。

## 四、以后怎样修改参数

### 1．打开本地工具

双击 **`love-wheel-editor.html`**，用电脑浏览器打开。它已包含所有运行内容，不需要安装软件或登录网站。它用于编辑配置，不是给她抽奖的页面。

工具内显示的概率是给你核算的，游戏页面仍然隐藏概率。编辑工具与游戏奖券记录分开，不会因编辑参数而清空她的奖券。

### 2．修改页面和玩法参数

| 参数 | 用途与范围 |
|---|---|
| 网站名称 | 顶部名称，最多 24 个字符 |
| 她的称呼 | 例如“宝宝”，最多 20 个字符，可留空 |
| 标题前半句／重点文字 | 例如“今天也”与“偏爱你”，各最多 16 个字符 |
| 首页副标题 | 例如“好运归你，兑现归我。”，最多 120 个字符 |
| 转盘时长 | 1–8 秒，默认 3 秒 |
| 刮开揭晓阈值 | 刮开面积达到这个比例时自动揭晓，10–80 的整数，默认 40；不是中奖概率 |
| 谢谢惠顾比例 | 1–99 的整数，默认 30；修改其他奖品权重时，工具会继续保持这里设置的比例 |

手机或电脑开启系统“减少动态效果”时，游戏会缩短转动动画，方便使用。

### 3．修改奖励

可以按名称搜索、按分类筛选，然后修改奖品卡片上的内容：

- **真实名称、兑现内容、揭晓留言**：决定抽中后看到什么。
- **权重**：决定这件奖励在所有真实奖励中的相对机会；必须是 1–100000 的整数。
- **预算**：用于你自己估算支出，不决定抽奖概率，也不会自动付款。改预算时如需改变兑奖约定，还要同步改“兑现内容”。
- **启用／停用**：停用后不再抽到、也不在玩家清单中展示，但条目和旧奖券继续保留。
- **是否盲盒**：开启后，玩家清单只展示封面名称和提示。
- **盲盒封面名称、盲盒提示**：用来保留悬念，不要把完整真实内容又写进提示里。

工具会显示每件奖品的实际概率，方便比较。**普通奖励和盲盒共享真实奖励的总份额，盲盒不是额外赠送的一次抽奖。**

例如，谢谢惠顾保持 30%，其余奖励合计就是 70%。你提高某件奖品的权重，只会调整这 70% 之内的分配；其他奖励所占比例相应降低。

### 4．增加或暂停奖励

使用“添加奖品”，选一个现有分类并填写完整内容。想做盲盒就打开盲盒选项，补上封面名称和提示。工具会分配新的唯一标识，并把新项目追加到分类末尾。

不再想抽到某个奖品时，取消勾选 **“参与抽奖”** 即可停用。请保留已经使用过的奖品标识，不要手动删除、改名或挪动标识。工具导入配置时会检查既有条目，避免旧记录失去对应关系。

### 5．保存配置，并导出网页

1. 用“导出配置 JSON”保存一份自己的参数备份。
2. 确认校验通过，在工具中查看玩家奖品卡片预览；预览用于检查文案与盲盒遮盖，不等同于完整游戏运行测试。
3. 点击主按钮 **“导出网页 index.html”**。
4. 将新下载的完整首页上传到仓库原来的 `dist` 文件夹，覆盖 `index.html` 并提交。
5. 等待发布完成，用原网址确认新内容。

**本地编辑、保存草稿或导出文件，不会自动修改 GitHub 上的网站。必须上传新版首页，其他设备才会看到变化。**

浏览器可能把重复下载的文件命名为 `index (1).html`。上传前请把这次新导出的文件恢复为 **`index.html`**，不要误传上一次下载的旧文件。

工具会尝试保存本地草稿，并显示状态；浏览器不允许本地页面存储时仍可编辑和导出，请及时保存 JSON。之后在另一台电脑打开工具，也可以导入自己的配置 JSON。配置备份只包含奖品和参数，不包含她的中奖记录。

## 六、旧奖券、网址和二维码

- 原有奖品的 ID 和默认顺序保留；旧奖券继续使用中奖时保存的内容，不会被新参数改成另一份承诺。
- 停用奖品只影响之后的抽取，已抽到的券仍有效。
- 未刮开的结果继续保留，不会因为更新而重新抽一次。
- 同一浏览器继续使用同一正式网址并保留网站数据时，沿用原来的奖券记录。
- 原来指向 `/love-wheel/dist/` 的二维码继续有效。

请固定使用 **`https://bbtnoctrl.github.io/love-wheel/dist/`**。本游戏按网址路径和查询参数区分本地记录；改成 `/dist/index.html`、换浏览器或在页面地址后加 `?v=...`，可能读取另一份记录。静态资源内部的版本参数由导出工具处理，不需要你修改游戏网址。

如果暂时看到旧页面，先等待发布完成，再强制刷新；不要清除网站数据。本次不含云端奖券同步或可恢复的奖券整体备份，已有“保存奖券图片”功能继续可用。

## 七、需要改源码时

普通修改用编辑工具即可。需要进一步开发时，完整源码在 `source/`：

| 路径 | 用途 |
|---|---|
| `dist/config.js` | 默认页面参数和全部奖品配置 |
| `dist/config-schema.js` | 参数校验、固定空奖比例和权重计算 |
| `dist/core.js` | 抽奖、揭晓、兑奖和旧券读取 |
| `dist/app.js` | 转盘、刮卡、盲盒界面、图片和分享交互 |
| `dist/index.html`、`dist/styles.css` | 拆分版页面和样式 |
| `dist/share.js`、`dist/vendor/`、`dist/assets/` | 分享、二维码库及图标 |
| `editor/` | 离线编辑工具及网页／ZIP 导出逻辑 |
| `build-singlefile.py` | 从拆分源码生成完整游戏 HTML |
| `build-editor.py` | 把编辑器和当前游戏源码打包成离线工具 |
| `checks/`、`package.json` | 配置、旧券兼容、抽奖和导出的验证用例 |

如果改了源码，进入 `source` 目录执行：

```bash
python3 build-singlefile.py
python3 build-editor.py
```

Windows 已安装 Python 3 时可把 `python3` 换成 `py -3`。生成的 `love-lucky-wheel-single.html` 是完整游戏，复制一份改名为 `index.html` 后上传。生成的 `love-wheel-editor.html` 是包含这次最新源码的离线工具。

**改完游戏源码后，要重新生成编辑工具。** 旧编辑工具内嵌的是旧运行代码，继续用旧工具导出会把网页恢复为旧功能版本。你的奖品参数可通过导入 JSON 带入重新生成的工具。

编辑工具还提供多文件源码 ZIP 导出，适合明确选择拆分方式维护的人。若使用它，要解压后将全部文件和子目录放回仓库 `dist` 中；不能把拆分入口单独上传。单文件和拆分方式二选一，推荐日常使用单文件首页。
